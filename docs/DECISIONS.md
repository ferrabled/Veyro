| D16 | 2026-09-03 | **Boards are Daily + All-time**, keyed `(date, content_version, world_id)` and split **standard** (tilt/touch) vs **camera**. A run that started on the camera and fell back to tilt submits as `camera_fallback` and ranks on the standard board, never the camera one — deliberately asymmetric with the local `BestBoard`, which still scores it as the camera run the player chose. Free-mode runs are history-only and never ranked. |
| D17 | 2026-09-19 | **Score formula is FROZEN**: whole metres + coin points, a coin worth 10 × a multiplier that steps every 3 coins and caps at ×5 (`ScoreState`). Balance via chunk difficulty and speed instead. Frozen because the shared board makes old scores incomparable across a change AND the server now validates submissions against this exact economy (`supabase/functions/_shared/validate.ts`) — changing the formula without moving `game_config` and the validator in the same change would flag every honest run. Closes OPEN_QUESTIONS 6. |
| D18 | 2026-09-19 | **CAPTCHA on anonymous sign-ups stays OFF.** Supabase Auth supports hCaptcha/Turnstile, but enforcement applies to the signup endpoint itself: turning it on today would break sign-in for **every client already in the field**, and the Unity client cannot render a challenge without adding a WebView dependency (gotcha #10 APK surface, plus a challenge screen on first launch of a game). The lid on bot signups is the per-IP anonymous rate limit + per-user submission quotas + flagged-run caps (migration `0004`) — that is **throttling, not bot prevention**; a patient attacker can still mint accounts. Revisit only with a WebView-based flow, and only if board pollution is actually observed. Closes OPEN_QUESTIONS 17. |
